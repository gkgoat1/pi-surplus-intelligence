## 2. What it means

The picker now offers all three new gateways with real catalogs fetched at
startup — no accounts needed, since all three expose public `/v1/models`
endpoints (a fact the Phase 1 probe established and this phase spent). The
`surp/free` smoke returned a completed chat answer over the wire with zero
credentials, which is the shape every later phase builds on. The one behavior
change to existing code — per-provider retry budgets — exists solely to honor
Bu0y's double-pay warning.

## 3. Still open

- Surp's paid routes return their 402 challenges, but nothing in the extension
  signs them yet; the payment loop from Phase 1 is not wired into Pi's fetch
  path (that is Phase 3).
- The live settled payment from Phase 1 remains blocked on a funded wallet.
- `X-Cost` from Ruvicode is not yet captured into diagnostics; the header
  path through pi-ai's built-in streams was not reachable without forking
  them, so the capture point is deferred to Phase 3's fetch wiring, where the
  hook sees every response.
- Surp combo entries report `resolved_model` at catalog time; Pi's picker
  shows the live pick in the model name, which may drift between discovery
  and request.
